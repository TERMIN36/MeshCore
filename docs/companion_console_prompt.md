# Консоль компаньона в мобильном приложении Termin36

В сборке **Termin36** для прошивки Мешкартель экран **Консоль** уже есть: терминал выполняет команды на самом компаньоне по Bluetooth, Wi‑Fi или USB (тот же канал Link). Это локальный CLI устройства, не радиосообщение и не контакт **Console** на экране платы.

Ниже — протокол и поведение экрана для разработчиков и для сверки с прошивкой. Пользователям: подключите Companion в приложении и откройте **Консоль**; на [meshcoretel.ru](https://meshcoretel.ru/ru) — как скачать приложение.

Прошивка отвечает командой `CMD_CONSOLE` (байт `0x42`) и кадром `PACKET_CONSOLE` (байт `0x1D`). Не открывай чат с контактом `Console` и не шли `CMD_SEND_TXT_MSG` на ключ `MC-CLI`: тот путь оставлен для старого приложения и для терминала не подходит.

Стек любой. Ниже описан протокол и поведение экрана, а не фреймворк.

## Канал

Тот же UART, что у остального протокола компаньона, поверх BLE.

- Сервис: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- Запись (приложение → устройство), RX: `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- Уведомления (устройство → приложение), TX: `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`

Одно уведомление TX — один кадр. У кадра нет префикса длины: длина — это длина уведомления. В RX пиши кадр целиком, с ответом (write with response). Запроси MTU не меньше 200, лучше 512. Пока уведомления TX не включены, команды не шли.

На Wi-Fi и USB тот же payload обёрнут в 3 байта: для записи `'<'` и длина uint16 little-endian, в ответе `'>'` и та же длина. На BLE этой обёртки нет.

Связь однозадачная. Пока ждёшь ответ, не шли следующую команду, ни консольную, ни любую другую. Таймаут на кадр — 5 секунд. По таймауту разблокируй ввод и покажи, что ответа не было.

Перед консолью устройство уже должно быть в сессии: после включения уведомлений отправь `CMD_APP_START` (`0x01`, семь нулевых байт, затем имя приложения) и дождись `0x05`, затем `CMD_DEVICE_QUERY` (`0x16 0x03`) и дождись `0x0D`. Консоль — отдельный экран этой сессии, не шаг контактов и не синхронизация сообщений.

## Кадры консоли

Выполнить строку:

```
байт 0: 0x42
байт 1: 0x01
байты 2…: строка UTF-8 без нуля на конце
```

Не длиннее 160 байт. Без `\n` и `\r`: прошивка их срежет, но лимит считается вместе с ними. Пустую строку не отправляй.

Дочитать следующий кусок:

```
42 02
```

Ответ:

```
байт 0: 0x1D
байт 1: флаги
байты 2…: текст этого куска
```

Флаги:

- бит 0 (`0x01`) — текст ещё есть, сразу шли `42 02`
- бит 1 (`0x02`) — буфер 2048 байта кончился, хвост потерян

Кусок не длиннее 174 байт. Нуля в конце нет, кусок может быть пустым. Склеивай байты всех кусков одной команды и только потом декодируй UTF-8: символ может разорваться между кадрами. Пока бит 0 установлен, ввод новой строки запрещён.

Если первый байт ответа `0x01`, это ошибка кадра (нет операции или операция неизвестна). Покажи код из второго байта, если он есть, и снова открой ввод.

Когда бит 0 сброшен, команда закончена. Лишний `42 02` без остатка отвечает двумя байтами `1D 00`.

Пример. Команда `ver`:

```
42 01 76 65 72
```

Ответ вроде `1D 00` и текст версии. Если ответ длиннее одного кадра, первый кадр будет `1D 01` плюс кусок, дальше `42 02`, пока флаг `0x01` не исчезнет.

`reboot` отвечает текстом `  > rebooting` и устройство перезагружается. После этой строки жди обрыв и подключайся снова, не считай обрыв ошибкой команды.

`set link ble|wifi|usb|off` на другой транспорт может оборвать текущую связь раньше ответа. Настройка уже записана. Переподключайся по новому каналу. Пароль Wi-Fi уходит этой же командой открытым текстом поверх уже сопряжённого канала: не пиши его в логи.

Строка длиннее 160 байт не выполняется. В тексте ответа будет `  Error: command too long`.

## Экран

Моноширинный терминал. История прокручивается вверх, новая выдача дописывается вниз, поле ввода закреплено снизу. Enter отправляет строку.

Пока куски не дочитаны, поле ввода неактивно. По таймауту, ошибке `0x01` и нормальному концу (бит 0 сброшен) поле снова активно.

Если в последнем кадре установлен бит 1, после текста допиши отдельной строкой, что вывод обрезан.

Историю сессии держи в приложении. Устройство прошлое не помнит и приглашение само не шлёт. При открытии экрана можно один раз само послать `help`.

Команды, которые понимает прошивка (строка `help` печатает тот же список):

- `help` или `?`
- `ver`
- `clock` — время UTC, unix
- `clock.node` — список узлов часов
- `clock.node remove <index>`
- `clock pull`
- `set pin N` — PIN BLE, шесть цифр
- `set tz ±H` или `set tz ±H:MM`, диапазон UTC−14…UTC+14. Без аргумента показывает текущий пояс
- `set time YYYY-MM-DD HH:MM` или с секундами. Без аргумента показывает местное время
- `set clock.node off` или `set clock.node <pubkey hex>`
- `set lang ru` или `set lang en`
- `set tx.led on` или `set tx.led off`
- `set link ble|wifi|usb|off`
- `set wifi.ssid <имя>`
- `set wifi.password <пароль>`, очистка: `set wifi.password -`
- `ls` и `ls <path>`
- `cat UserData/…` или `cat ExtraFS/…` — файл как hex
- `rm <path>`
- `rebuild` — стирает файловую систему и собирает заново
- `erase`
- `reboot`

`rebuild` и `erase` необратимы. Перед отправкой спроси подтверждение. Остальные строки уходят сразу.

Неизвестная команда — это не обрыв протокола: в тексте будет `  Error: unknown command`. Покажи текст как есть.
